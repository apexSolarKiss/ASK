asset-pipeline-ASK // AP-ASK

explore >> repo >>

AP-ASK articulates and encodes a brand’s visual language as a clear, reusable system for image production. It draws on the brand’s imagery, references, and products, together with the accumulated knowledge of its creative team. It separates what must remain true from what may vary creatively, and makes explicit what each reference is meant to guide. It carries the brand’s direction from the brief through production, review, selection, and approval. Because AP-ASK is tool-independent, that direction can inform the work of photographers and art directors, direct AI image models, or be built into an Airtable-based workflow. The point is to not let the tool define the brand, but rather to keep the brand’s own creative direction intact as the tools change.

AP-ASK is a developing open-source reference architecture, not a finished production platform.

method + grounding

ASK calls the underlying method “bounded generativity”: define the grammar, permit bounded variance, make selection + governance explicit. A deterministic governance architecture brackets the generative execution span. The decision-owner's mandate is translated into roles, decision rights, constraints, reference roles, tool permissions + review paths. Agents can determine how to proceed within that structure; changes to purpose, scope or acceptance standards follow an explicit decision path. Precise language does not, by itself, make the tools comply.

The operating model is architect + domain authority. ASK designs the architecture + encoding; the domain authority owns the substance + terminal judgment. In commercial visual production, ASK holds both roles.

Corporate law informs how the practice specifies authority, delegation + limits. Production experience grounds that work in briefs, budgets, partners, approvals + predictable workflow failures. The method can extend across domains; the current practice is anchored in creative operations + commercial visual production.
